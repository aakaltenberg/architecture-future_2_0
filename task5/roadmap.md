# Стратегический роадмап внедрения Data Mesh

## Ключевые роли

| Роль                   | Обязанности                                                                                   |
|------------------------|-----------------------------------------------------------------------------------------------|
| **Data Product Owner** | Владелец доменных данных, отвечает за качество, доступность и развитие Data Product.          |
| **Data Engineer**      | Проектирует и строит ETL/ELT, потоковую обработку, обеспечивает надёжность конвейеров.        |
| **BI-аналитик**        | Создаёт отчёты и витрины в Self-Service портале, консультирует бизнес-пользователей.          |
| **Platform Engineer**  | Развивает центральную Data Platform (Kafka, Spark, Kubernetes, storage).                      |
| **Data Governance Officer** | Отвечает за стандарты, каталог данных, качество, соответствие нормам.                    |
| **Enterprise Architect** | Определяет целевые архитектурные решения, границы доменов.                                |

## Этапы внедрения

### Этап 0: Подготовка (0–3 месяца)

**Цели:** сформировать команду, обучить ключевых сотрудников, выбрать пилотный домен, настроить базовую инфраструктуру.

- Выбрать пилотный домен (рекомендуется «Финансовые расчёты» или «Пациентский поток»).
- Создать центральную команду Data Platform (2–3 инженера).
- Настроить облачную среду (VPC, IAM, Kubernetes, Object Storage).
- Развернуть Kafka, OpenMetadata, ClickHouse.
- Провести обучение по DDD и Data Mesh для всех участников.
- Определить первые Data Contracts.

**Ключевые бизнес-цели:** снижение time-to-market для первых аналитических отчётов, проверка концепции.

### Этап 1: Пилот (3–9 месяцев)

**Цели:** внедрить Data Mesh в одном домене, показать ценность, отладить процессы.

- В пилотном домене выделить bounded contexts, агрегаты, события.
- Реализовать потоковую передачу данных через Kafka (CDC из источника).
- Создать доменный Data Product (витрина) в ClickHouse.
- Подключить Self-Service BI портал для бизнес-пользователей.
- Настроить каталог данных и lineage.
- Оценить результаты: скорость получения отчётов, нагрузка на команду.

**Ключевые бизнес-цели:** сокращение времени формирования отчётов с часов до минут, повышение удовлетворённости пользователей.

### Этап 2: Масштабирование на критичные домены (9–18 месяцев)

**Цели:** распространить подход на остальные домены, включая медицинский и финтех.

- Ввести антикоррупционные слои для интеграции с legacy (Camel, DWH) через события.
- Расширить Data Platform: добавить Flink для потоковых агрегаций, dbt для трансформаций.
- Для каждого нового домена:
  - назначить Data Product Owner;
  - выделить Data Engineers;
  - определить события и контракты;
  - создать доменные витрины.
- Обеспечить соблюдение Data Governance: качество, безопасность, аудит.
- Начать вывод из эксплуатации PowerBuilder и частичную миграцию DWH.

**Ключевые бизнес-цели:** поддержка новых бизнес-направлений (фармацевтика, электроника), улучшение качества данных, снижение рисков.

### Этап 3: Полная трансформация (18–36 месяцев)

**Цели:** достичь целевой слабосвязанной событийной платформы, отказаться от legacy.

- Заменить оставшиеся синхронные интеграции (Camel) на события.
- Полностью мигрировать данные из SQL Server 2008 в облачные хранилища.
- Вывести из эксплуатации Power BI (или оставить только для рудиментарных задач).
- Внедрить near-real-time аналитику по всем ключевым показателям.
- Автоматизировать Data Governance и мониторинг качества.
- Обеспечить соответствие требованиям регуляторов (152-ФЗ, GDPR) во всех доменах.
- Провести обучение всех бизнес-пользователей работе с Self-Service BI.

**Ключевые бизнес-цели:** запуск новых финтех- и медицинских сервисов, выход на новые регионы, обработка событий в реальном времени, снижение TCO.

## Матрица ответственности (RACI)

| Активность                    | Data Product Owner | Data Engineer | BI-аналитик | Platform Engineer | Data Governance Officer | Enterprise Architect |
|-------------------------------|--------------------|---------------|-------------|-------------------|-------------------------|----------------------|
| Определение границ домена     | C                  | C             | I           | I                 | C                       | A/R                  |
| Разработка конвейеров данных  | I                  | R             | C           | C                 | I                       | I                    |
| Создание витрин               | A                  | R             | C           | C                 | I                       | C                    |
| Настройка каталога данных     | C                  | I             | I           | R                 | A                       | C                    |
| Обеспечение качества данных   | A                  | R             | C           | C                 | R                       | C                    |
| Мониторинг и эксплуатация     | I                  | C             | I           | R                 | I                       | I                    |

**Обозначения:** R – Responsible (исполнитель), A – Accountable (ответственный), C – Consulted (консультирует), I – Informed (информируется).
